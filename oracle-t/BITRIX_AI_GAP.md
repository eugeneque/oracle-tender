## Что изменилось с 11.11

- **Журнал событий работает без ручного включения** (раздел 100, 12.11): каждая выгруженная в
  Bitrix24 закупка сама встаёт под наблюдение (проверка раз в 30 минут), события уходят на портал
  тем же каналом. Раньше наблюдение включали вручную, и портал после выгрузки ничего не получал —
  поэтому пп. 48–64 на деле не доходили до Bitrix24.
- **Первая загрузка — не изменение** (общее правило «при первичной загрузке без истории не
  выдумывай изменение», пп. 52, 64): если документы при выгрузке ещё не скачивались, их появление
  не даёт «Добавлен документ» на каждый файл.
- **Разбор помечается «Информация неактуальная»**, если после него изменились НМЦК, обеспечение,
  документы, ТЗ/договор или вышли разъяснения (пп. 53–55, 59, 60) — в Сове, на портал не уходит.
- **Группа требований на портале** — `position_scope` (`position`/`all`/`unknown`) в строках
  требований ТЗ (11.11, после сверки): требование к позиции, ко всей закупке или «не ясно»;
  связь не выдумывается (общее правило «не создавай связи, которых нет в источниках»).
- **НМЦК с НДС и без НДС из документации** (раздел 106): разбирается кодом с цитатой, но в
  Bitrix24 не передаётся — поля под цену без НДС в API 1.7.0 нет (нужно согласовать расширение).
- Позиции и условия договора для Bitrix24 считаются одним запросом к модели (12.11) — дешевле,
  на состав данных не влияет.

## Общие правила для промптов — как соблюдаются

| Правило | Статус |
|---|---|
| Цитата и документ у факта | есть у условий поставки и договора, требований ТЗ и квалификации, итогов протоколов; нет у `contract_risk` и выводов-оценок |
| «Не указано» ≠ «нет условия» | у условий договора и обеспечения («не требуется» — только с цитатой); в остальных блоках не различается |
| Противоречия — оба значения с источниками | только итоги протоколов (→ ручная проверка) |
| Часовой пояс | даты уходят с поясом: пакет ИИ — по Москве (`+03:00`), события журнала — в UTC (`Z`); пояс площадки, если он другой, не извлекается |
| Суммы не заменять нулём | соблюдается: нет значения — поле пустое |
| Было/стало, без выдуманных изменений | события журнала (раздел 84) и первая загрузка (раздел 100) |
| Идентификаторы, повтор, защита от дублей — у обработчика | `event_id`, `supersedes_event_id`, постоянные ключи строк, журнал запросов |
| Лот не смешивать с процедурой | **нет**: сущности «лот» нет, всё `record_type=SINGLE` (п. 1) |

## Что есть (опора)

- **Канал** — `bitrix_ai_service` (раздел 66): подписанный JSON, `schema_version 2`, постоянные
  ключи строк, `full_snapshot`, журнал `bitrix_ai_requests`; данные — у основной записи закупки
  (раздел 93).
- **Требования ТЗ** по позициям спецификации (разделы 74, 94).
- **Условия поставки** — `delivery_terms_service` (раздел 85): модель поставки, места и
  грузополучатели с ИНН/КПП, график, заявки.
- **Условия договора и обеспечения** — `contract_conditions_service` (раздел 95): 16 видов
  условий с суммой, процентом, видом дней, событием-основанием и цитатой.
- **Журнал событий** — `tender_monitor_service`/`tender_event_service` (раздел 84): коды портала
  1.7.0, `old_value`/`new_value`, `event_id`, `supersedes_event_id`, повтор с тем же содержимым.
- **Документы процедуры** — строки `procurement_document` (раздел 85).
- **Заточенность ТЗ** — `detect_brand_lock` → `fas_signal`.
- **Итоги из протоколов** — `protocol_results_service` (раздел 96): участники с ИНН и ценами,
  допуск и причины, победитель из итогового протокола, наш результат по ИНН, `RESULT_CHANGED`.

## Сквозные требования, которых пока нет

1. **Лот как сущность** и привязка к нему документов, позиций, требований, событий, итогов.
2. **Версионность документов**: хранить прошлую редакцию и сравнивать пункты (пп. 14, 52–54, 90, 94).
3. **Формат факта везде**: цитата есть у условий поставки и договора, требований (в т. ч.
   квалификации) и итогов; нет у рисков договора, нет уверенности по полям (п. 86).
4. **Часовой пояс и даты не из ЕИС** (пп. 2, 3, 56–58 для коммерческих площадок).

## Следующие шаги

Без изменений с 11.11 — ни один шаг пока не начат.

1. **Прогон на 5–10 реальных закупках** условий поставки и договора; сверка со специалистом;
   передать специалисту Bitrix24 список полей `contract_condition` для русских подписей в
   `assets/app.js`.
2. **Квалификация (пп. 9–13):** строки `qualification` с порогом, периодом, подтверждением и
   цитатой — тип уже есть в API; сопоставление (п. 11) — после справочника компании.
3. **Протоколы:** прогон раздела 96 на реальных протоколах; раунды цен (`price_round`),
   редакции протоколов, запись итога в историю участий.
4. **Разъяснения (пп. 33–34):** проект запроса — строки `clarification`.
5. **Лоты (п. 1)** — фундамент для событий по лотам и сделок лотов; требует согласования с
   Bitrix24 (`record_type=PROCEDURE/LOT`).
6. ФАС (пп. 37–47) и после победы (пп. 88–92, 94) — после лотов и версий документов.
